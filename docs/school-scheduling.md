# ระบบจัดตารางเรียนทั้งโรงเรียน

ก่อนเผยแพร่โค้ด ให้รัน `supabase/migrations/053_school_schedule_solver.sql` แล้วตามด้วย `054_learner_development_subject.sql` และ `055_substitute_batch_save.sql` จากนั้นรัน `056_manual_schedule_activities.sql` ใน Supabase SQL Editor ไฟล์หลังรองรับ “กิจกรรมพัฒนาผู้เรียน” เป็นวิชาเดียวในตาราง โดยไม่เพิ่มวิชาให้คะแนนหรือเปลี่ยนหัวข้อประเมินกิจกรรมเดิม

## การใช้งาน

1. กำหนดรายวิชา ชั่วโมงต่อปี และครูในเมนูจัดครูเข้าสอนให้ครบ
2. กิจกรรมที่เปิดใช้ในตั้งค่า → กิจกรรมพัฒนาผู้เรียน จะเป็นตัวเลือกแยกรายการในตารางทุกห้อง ใช้ชื่อเต็มจากโรงเรียน ไม่ต้องเพิ่มครูหรือคาบ และเลือกลงเองเท่านั้น ระบบอัตโนมัติไม่เพิ่มกิจกรรมและคงคาบกิจกรรมเดิมไว้ แม้เลือกจัดรายวิชาที่ไม่ล็อกใหม่
3. เลือกวิชาหรือกิจกรรมลงช่องที่ต้องการ กดล็อกเพื่อเก็บคาบนั้นระหว่างจัดอัตโนมัติ ล็อกช่องว่างได้เพื่อกันเวลาไว้
4. กดจัดอัตโนมัติห้องนี้หรือทั้งโรงเรียน ค่าเริ่มต้นเติมช่องว่าง หากเลือก “จัดคาบที่ไม่ล็อกใหม่” ระบบจะคำนวณใหม่ครบก่อนแทนตารางเดิม
5. หากจัดไม่ได้ ระบบจะแจ้งสาเหตุและไม่เปลี่ยนตารางเดิม เช่น ครูสอนเกิน 30 คาบ คาบห้องเกิน 30 ครูไม่ครบ หรือคาบที่ล็อกชนกัน ห้องที่ยังไม่มีรายวิชา/กิจกรรมจะถูกข้ามพร้อมแจ้งชื่อห้อง

ตารางสอน ภาระงาน ตรวจความขัดแย้ง สอนแทน และส่งออกตาราง รวมกิจกรรมด้วย การคัดลอกตารางจับคู่รายวิชาหรือกิจกรรมเดียวกันและรักษาคาบปลายทางที่ล็อก หากจับคู่ไม่ได้หรือครูชนกันจะไม่บันทึก

ตารางเป็นรายปี จันทร์–ศุกร์ วันละ 6 คาบ โควต้ารายวิชาใช้ชั่วโมงต่อปีหาร 40 และปัดเป็นจำนวนเต็มอย่างน้อยหนึ่งคาบตามระบบเดิม กิจกรรมจากการตั้งค่าไม่รวมโควต้าจัดอัตโนมัติ และรายการใหม่ไม่จองเวลาครู ครูหนึ่งคนสอนได้หนึ่งห้องในแต่ละคาบ การจัดอัตโนมัติค้นหาแบบมีขีดจำกัดเวลา จึงอาจขอให้ลดคาบที่ล็อกเมื่อเงื่อนไขซับซ้อนมาก

## การตรวจสอบ

`npm run test:schedules` ทดสอบตัวจัดตาราง การจัดใหม่/คัดลอก/ล็อก/สิทธิ์ และ PostgreSQL จำลองด้วย PGlite รวมการ rollback ข้อมูล สถานะตารางที่เปลี่ยนระหว่างทำงาน เวลาพักเที่ยง และสอนแทน ไม่ติดต่อฐานข้อมูลจริง

`npm run build` ตรวจการสร้างเว็บ การตรวจ TypeScript ต้องรัน `npx tsc --noEmit` แยก เพราะค่าเดิมของโปรเจกต์ตั้ง `ignoreBuildErrors: true`

## สอนแทนและ PDF
นำเข้าคาบของครูที่ลา แล้วเลือกเฉพาะครูที่ว่างจากตารางประจำ ไม่มีการลา และยังไม่ถูกเลือกสอนแทนคาบเดียวกัน กด “บันทึกทั้งหมด” ครั้งเดียว ระบบตรวจซ้ำในฐานข้อมูลและไม่บันทึกบางส่วนเมื่อมีข้อผิดพลาด หลังบันทึกเลือกภาคเรียนของเอกสารแล้วดาวน์โหลด PDF มีช่องครูผู้ลา หัวหน้าวิชาการ ผู้อำนวยการ และครูสอนแทนเซ็นหลังสอนรายคาบ ชื่อหัวหน้าวิชาการดึงจากผู้ใช้บทบาท academic_head ที่เปิดใช้งาน และชื่อผู้อำนวยการจากข้อมูลโรงเรียน

## ตรวจสอบ
`npm run test:schedules` ครอบคลุมฐานข้อมูลจริงจำลองด้วย PGlite รวมกิจกรรมไม่มีครู โควต้า 1 คาบ การบันทึกสอนแทนทั้งชุด และข้อมูลที่ถูกแก้พร้อมกัน ตรวจ PDF ตัวอย่างด้วย PDF.js เพื่อดูฟอนต์ไทยและช่องลงชื่อ

Migration 056 สร้างตัวเลือกกิจกรรมให้ห้องเดิมและห้องใหม่ รวมถึงเมื่อเพิ่มหรือเปิดใช้กิจกรรมในตั้งค่า ไม่ลบคาบเดิมหรือข้อมูลประเมิน ปิดกิจกรรมแล้วจะไม่เสนอให้เลือกเพิ่ม แต่คาบเดิมยังแสดงและนำออกได้ รายการรวมจากรุ่นก่อนเก็บไว้เฉพาะที่เคยลงตารางแล้ว

## คาบสุดท้ายและผู้ลงนาม
ตัวจัดอัตโนมัติค้นหาตารางที่ใช้คาบ 1–5 ก่อน แล้วเพิ่มจำนวนคาบที่ 6 เท่าที่จำเป็น ภายใต้ขีดจำกัดการค้นหา คาบเดิมและกิจกรรมที่เก็บไว้ยังเป็นเงื่อนไขบังคับ เอกสารตารางเรียนมีโลโก้จากข้อมูลโรงเรียน พร้อมช่องหัวหน้าวิชาการและผู้อำนวยการลงนาม เอกสารสอนแทนใช้ academic_head_name และ director_name/acting_director จากข้อมูลโรงเรียน ไม่สุ่มเลือกผู้ใช้ตามบทบาท
